# 后台生成任务与跨页面进度 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将同步长连接生成改成可持久查询的后台任务，并在主页输入框下方和跨页面导航中持续展示真实生成状态。

**Architecture:** 后端以文件型 `GenerationJobStore` 保存 24 小时短期任务，`GenerationJobRunner` 复用现有工作流注册表并接收进度事件；前端由路由上层的 `GenerationJobProvider` 创建和轮询任务，将活动任务上下文暂存 IndexedDB，并继续使用现有历史物化逻辑保存终态结果。现有 `/api/generate` 保持兼容，首页改用 `/api/generation-jobs`。

**Tech Stack:** TypeScript 5.9、Express 5、React 19、React Router 7、IndexedDB/idb、Vitest、Testing Library、Supertest、Node 文件系统原子写入。

## Global Constraints

- 同一浏览器只允许一个非终态主页生成任务。
- 主页详细状态必须显示在输入框下方；其他页面只在历史图标旁显示轻量圆点。
- 第一版不提供真正的第三方模型请求取消，也不承诺已提交请求停止计费。
- 任务文件保留 24 小时，位于 `data/generation-jobs/`，不得提交 Git。
- 完整用户历史仍保存在浏览器 IndexedDB；任务存储不是长期业务历史。
- API 不得返回提示词、密钥、上游正文或物理路径。
- 现有四工作流、`GenerateRequest`、`GenerateResult`、Provider 和 `/api/generate` 必须保持兼容。
- 每个任务先写失败测试，再写最小实现；每个任务以中文 Commit Message 独立提交。

export type GenerationJobRecord={
