# 文旅营销素材生成设计

> 日期：2026-08-28
> 项目：project002文旅营销素材生成
> 状态：已确认，进入实施计划

## 1. 目标

面向文旅行业内部营销人员，提供一个极简的内容生成入口：用户选择模板并输入一句话需求，系统根据模板提示词调用文案模型和图片模型，返回一整套可直接发布的营销素材。

用户不需要理解提示词、模型或复杂参数。

## 2. MVP 范围

### 必须实现

- 前端提供四个模板选择：固定 IP 形象、旅游攻略知识卡片、风景拼图、人物拼图。
- 前端提供一句话输入框和一键生成按钮。
- 后端校验模板编号和输入内容。
- 后端根据模板装配提示词并调用文案/图片模型适配器。
- 前端展示标题、正文、标签和图片组。
- 支持分别复制标题、正文、标签。
- 支持下载单张图片和完整素材包。
- 使用占位提示词和 mock 模型时，项目可以在无外部模型密钥的情况下完整运行。
- 正式提示词接入时只修改模板文件或配置，不修改前端协议和生成主流程。

### 不做

- 登录、权限、历史记录、收藏和数据库。
- 多轮对话和自动规划型 Agent。
- 自动识别用户想使用的模板。
- 真实景区知识库和事实校验。
- 云端素材管理、二维码和社交平台自动发布。
- 视频生成。

## 3. 用户流程

```text
打开页面
→ 选择一个内容模板
→ 输入一句话需求
→ 点击“一键生成”
→ 等待生成完成
→ 查看整套素材
→ 复制文字或下载图片/素材包
```

用户输入示例：

```text
为贵州夏季避暑旅游活动生成一套年轻人喜欢的宣传素材
```

## 4. 模板与输出

四个模板共用输出协议，差异只存在于提示词、生成步骤、图片数量和视觉规格。

| 模板 ID | 默认输出 | 默认图片形式 |
|---|---|---|
| `ip-image` | 标题、正文、标签、IP 主视觉 | 1 张主图 |
| `travel-cards` | 总标题、正文、标签、攻略卡片说明 | 4 张知识卡片 |
| `scenery-collage` | 标题、正文、标签、景点卖点 | 1 张风景拼图 |
| `people-collage` | 标题、正文、标签、旅拍卖点 | 1 张人物拼图 |

后续队友可以调整图片数量、比例和提示词，但不能破坏统一输出协议；确需扩展字段时新增可选字段，不改变既有字段语义。

## 5. 数据协议

### 生成请求

```ts
type GenerateRequest = {
  templateId: string;
  userPrompt: string;
};
```

约束：`templateId` 必须来自后端已注册模板；`userPrompt` 去除首尾空白后不能为空，长度限制为 2—500 个字符；前后端都执行校验。

### 生成响应

```ts
type GenerateResponse = {
  requestId: string;
  templateId: string;
  title: string;
  body: string;
  tags: string[];
  images: Array<{
    url: string;
    filename: string;
    alt?: string;
  }>;
  warnings: string[];
};
```

`warnings` 用于报告图片生成失败、使用 mock 内容等非致命情况；文案失败时请求失败，图片失败时尽量保留已生成的文案。

## 6. 系统架构

```text
React 前端
  ├─ 模板选择
  ├─ 一句话输入
  ├─ 生成状态
  └─ 素材包展示/复制/下载
          ↓ HTTP
Node.js TypeScript 后端
  ├─ Generate API
  ├─ 模板注册表
  ├─ 提示词构建器
  ├─ 文案模型适配器
  ├─ 图片模型适配器
  └─ 素材包响应整理
```

核心边界：

- 前端只提交 `templateId` 和 `userPrompt`，不接触完整提示词和模型密钥。
- 模板模块只负责定义模板信息、提示词和生成策略。
- 模型适配器只负责把统一请求转换为具体模型调用，不承载业务模板规则。
- 生成服务负责编排模板和模型，不直接写前端展示逻辑。
- MVP 不保存用户输入和生成结果；素材通过本次响应提供给前端。

## 7. 模板接口

```ts
type TemplateContext = {
  userPrompt: string;
};

type GeneratedCopy = {
  title: string;
  body: string;
  tags: string[];
};

type MarketingTemplate = {
  id: string;
  name: string;
  buildCopyPrompt(context: TemplateContext): string;
  buildImagePrompts(context: TemplateContext, copy: GeneratedCopy): string[];
};
```

正式提示词到位后，由队友分别替换 `buildCopyPrompt` 和 `buildImagePrompts` 的内容；四个模板之间保持独立。

## 8. 生成策略

- 只需要文字的模板可以只调用文案模型。
- 需要图片的模板先生成结构化文案，再由模板根据文案生成图片提示词。
- 图片按模板要求串行或并行生成，由后端策略决定，前端不感知。
- 首版默认使用 mock provider，返回确定性的演示结果；配置真实 provider 后使用环境变量读取模型地址和密钥。
- 真实 provider 的返回结果必须先转换为统一的 `GeneratedCopy` 和图片结果，再返回 API。

## 9. 异常与状态

- 空输入或超过长度：前端阻止提交，后端返回 `400`。
- 不存在的模板：后端返回 `400`，前端提示模板不可用。
- 文案模型失败或超时：返回 `502`，前端保留输入并允许重试。
- 图片模型失败：返回文案和 `warnings`，前端显示图片失败提示。
- 生成中：按钮禁用并展示明确的加载状态，防止重复提交。
- 下载失败：不影响生成结果，前端提示用户单独下载图片。

## 10. 验收标准

- 四个模板均可被选择并成功提交。
- 输入一句话后，mock 模式能返回标题、正文、标签和对应图片数量。
- 结果页能分别复制标题、正文、标签。
- 结果页能下载图片，并能下载包含图片和文案的素材包。
- 重复点击不会产生并发重复请求。
- 无模型密钥时可以启动并完成 mock 端到端流程。
- 替换单个模板提示词不会修改其他模板和公共 API。
- 前端构建、后端测试和接口冒烟测试通过。

## 11. 后续扩展边界

后续新增文旅模板或其他行业模板时，只增加模板定义、模型策略和必要的展示字段；登录、历史、知识库、发布渠道适配属于独立版本，不进入本次 MVP。
