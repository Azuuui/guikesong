# 黔景智作后台生成任务与跨页面进度设计

> 日期：2026-08-30  
> 状态：已确认，待实施计划  
> 项目：黔景智作（QianScape AI / QSAI）

## 1. 背景与问题

当前生成采用单次长连接：主页发起 `POST /api/generate` 后持续等待完整结果。真实模型需要依次完成结构化内容、文案与多张图片，耗时可能达到数分钟。现有界面只显示转圈，用户无法判断任务是否真正开始、正在执行哪个阶段或是否已经卡住。

当用户从主页进入“全部模板”等页面时，主页组件卸载并取消前端等待；后端已经发出的模型请求仍可能继续执行，但完成结果无法回到已离开的页面，也不会可靠写入浏览器历史。这会造成结果丢失和真实模型费用浪费。

## 2. 目标

- 生成任务不依赖主页生命周期，切换页面后仍可完成。
- 主页在输入框下方显示可理解的真实阶段进度。
- 其他页面通过顶部历史图标旁的小圆点保留轻量状态入口。
- 页面刷新后可根据 `jobId` 恢复任务状态，不重复发起生成。
- 成功、部分成功和失败都有可追踪的终态；成功结果可进入本机历史。
- 复用现有四工作流、Provider、结果结构和 IndexedDB 历史，不重写生成业务。

## 3. 非目标

- 第一版不实现真正的第三方模型请求取消。部分服务在收到请求后仍会继续计费，不能向用户承诺已经终止。
- 不增加账号、云端用户历史或跨设备同步。
- 不提供多任务队列管理界面；同一浏览器第一版只允许一个主页生成任务处于非终态。
- 不把临时任务存储升级为长期业务数据库。

## 4. 总体方案

生成链路改为后端异步任务：

1. 前端提交生成参数至 `POST /api/generation-jobs`。
2. 后端完成请求校验，创建任务记录并立即返回 `202 + jobId`。
3. 后端在请求结束后继续调用现有工作流，并持续更新阶段、图片进度和终态。
4. 前端保存活动 `jobId`，轮询 `GET /api/generation-jobs/:jobId`。
5. 用户切换页面时轮询由应用级任务上下文继续维护，不随主页卸载。
6. 任务完成后，前端将最终结果物化到现有 IndexedDB 历史；点击状态区域进入结果页。

现有 `POST /api/generate` 暂时保留用于兼容和既有测试，但正式首页改用任务接口。两个入口必须复用同一请求解析和工作流注册表，禁止复制生成逻辑。

## 5. 后端设计

### 5.1 任务状态

任务使用以下稳定状态：

- `queued`：已创建，等待开始。
- `running`：工作流正在执行。
- `succeeded`：全部目标输出完成。
- `partial`：部分图片失败，但保留可用结果。
- `failed`：无法形成可用结果。

非终态为 `queued`、`running`；终态为 `succeeded`、`partial`、`failed`。

### 5.2 进度阶段

公共阶段只表达用户可理解的信息，不暴露 Provider、模型名或内部提示词：

- `preparing`：正在整理选题。
- `content`：正在生成内容清单或结构。
- `copy`：正在生成文案。
- `images`：正在生成图片。
- `finalizing`：正在整理生成结果。

图片阶段额外返回：

- `completedImages`
- `totalImages`

前端可据此显示“正在生成图片 1/2”。不同工作流内部步骤不同，但必须映射到这组公共阶段。

### 5.3 任务合同

创建任务：

```http
POST /api/generation-jobs
Content-Type: application/json
```

请求体继续使用现有 `GenerateRequest` 判别联合。成功返回：

```json
{
  "jobId": "uuid",
  "status": "queued",
  "createdAt": "ISO-8601"
}
```

查询任务：

```http
GET /api/generation-jobs/:jobId
```

返回内容包含：

```json
{
  "jobId": "uuid",
  "workflowId": "xhs-atlas",
  "status": "running",
  "phase": "images",
  "completedImages": 1,
  "totalImages": 2,
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "result": null,
  "error": null
}
```

终态成功或部分成功时 `result` 为现有 `GenerateResult`；失败时 `error` 只包含安全中文消息与稳定错误码。响应不得包含提示词、密钥、上游响应正文或物理路径。

### 5.4 任务存储

任务属于短期运行状态，不属于用户业务历史。第一版采用项目本地文件存储：

- 目录：`data/generation-jobs/`
- 每个任务一个 JSON 文件。
- 写入采用“临时文件 + 原子重命名”，避免进程中断留下半份 JSON。
- 任务默认保留 24 小时；启动时和创建新任务时清理过期记录。
- 目录加入 Git 忽略，不提交运行时结果。

这样可以在页面刷新或后端短暂重启后恢复查询，同时保持“完整历史只在浏览器 IndexedDB”这一产品边界。任务过期后返回安全的 404，前端提示任务已过期并允许重新生成。

### 5.5 工作流进度上报

扩展现有工作流上下文，增加可选的 `reportProgress` 回调。工作流只报告公共阶段和图片计数，不直接依赖任务存储。

任务运行器负责：

- 调用现有工作流注册表。
- 接收进度事件并写入任务存储。
- 捕获异常并转换为安全终态。
- 保存最终 `GenerateResult`。

没有传入 `reportProgress` 时，现有同步接口和工作流测试继续正常运行。

## 6. 前端设计

### 6.1 应用级任务上下文

新增应用级 Generation Job Context，挂载在路由之上，职责仅包括：

- 创建任务。
- 保存和恢复活动 `jobId`。
- 轮询任务状态。
- 暴露当前任务、终态结果和查询错误。
- 在终态时将结果写入现有 IndexedDB 历史，并保证同一 `jobId` 只写一次。

主页输入框组件只消费任务状态，不再持有长连接。离开主页不会终止轮询。

活动任务标识保存在 `localStorage`；完整结果仍写入现有 IndexedDB。页面加载时若存在活动 `jobId`，立即查询后端，而不是重新提交请求。

### 6.2 主页状态区域

状态区域固定放在生成输入框下方，副文案上方或与副文案合并布局，保持输入区视觉中心，不增加大面积卡片。

视觉规则：

- 使用小号正文、细进度线和一个状态图标。
- 宽度与输入框对齐。
- 与输入框间距紧凑，不制造大块留白。
- `running` 使用中性雾灰和轻微动态反馈，不使用警告红。
- `succeeded` 使用清晰但克制的成功色，并显示“查看结果”。
- `partial` 显示“部分素材已完成”，允许查看可用结果。
- `failed` 显示具体安全错误与“重新生成”。

任务非终态时保持当前输入与模板选择，但禁用再次提交，避免同一浏览器创建并行主页任务。

### 6.3 其他页面状态入口

在全部模板、模板详情、结果和历史等页面：

- 生成中：顶部历史图标旁显示小型进行中圆点。
- 完成后：圆点短暂增强亮度，直到用户查看任务或结果。
- 点击历史图标仍进入历史页；历史页顶部优先展示当前任务状态。
- 返回主页后恢复输入框下方的详细阶段。

小圆点只承担状态提醒，不显示长文本，不抢占顶部导航视觉中心。

### 6.4 轮询策略

- `queued`、`running`：每 2 秒查询一次。
- 页面不可见时降至每 5 秒一次。
- 达到终态后停止轮询。
- 连续网络失败采用递增退避，但不把任务直接标记失败。
- 单次查询失败显示“正在重新连接”，恢复后继续展示真实阶段。

### 6.5 历史与结果去重

任务终态且存在结果时：

1. 使用 `jobId` 作为幂等键检查本机历史。
2. 未保存时调用现有结果物化逻辑写入 IndexedDB。
3. 标记本地任务已保存。
4. 用户点击“查看结果”进入 `/results/:requestId`。

如果历史写入失败，结果仍可查看，同时显示现有“结果已生成，但本机历史保存失败”提示。

## 7. 错误处理

- 创建任务参数错误：直接显示现有业务校验信息，不创建任务。
- 模型阶段失败：任务进入 `failed`，记录安全阶段错误。
- 个别图片失败：沿用现有 `partial` 结果，保留文案和成功图片。
- 查询网络中断：只标记连接状态，不改变后端任务终态。
- 任务不存在或已过期：清除本地活动 `jobId`，提示重新生成。
- 结果结构不合法：前端拒绝写入历史，显示“生成结果校验失败”。

## 8. 测试与验收

### 8.1 后端

- 创建任务立即返回 `202`，不会等待完整生成。
- 任务按 `queued → running → succeeded/partial/failed` 转换。
- 四工作流公共阶段映射正确。
- 图片完成计数不会超过总数。
- 文件任务记录可在新建 Store 实例后恢复。
- 过期任务被清理，未知任务返回安全 404。
- 同步生成接口保持兼容。

### 8.2 前端

- 首页提交后输入框下方显示阶段状态。
- 切换至全部模板后任务继续轮询，历史图标显示小圆点。
- 返回主页后恢复同一个 `jobId`，不会重复创建任务。
- 刷新页面后恢复活动任务。
- 终态结果只写入历史一次。
- 成功、部分成功、失败和网络重连状态均有明确展示。
- 活动任务期间不能重复提交。

### 8.3 真实模式验收

使用“2个贵州景点”执行一次真实生成：

1. 创建任务后 2 秒内看到阶段状态。
2. 进入全部模板页面，顶部历史图标旁仍显示进行中圆点。
3. 返回主页，任务继续且 `jobId` 不变。
4. 完成后能够进入结果页，并在本机历史中只出现一次。
5. 整个过程中不再出现因页面切换导致的结果丢失。

## 9. 实施边界

- 先建立任务合同、Store 和 Runner，再接入工作流进度，最后改造前端上下文与界面。
- 不在本次顺带调整模型、提示词、模板排序或主页其他视觉规范。
- 运行时任务文件、真实生成图片和密钥均不得提交 Git。
