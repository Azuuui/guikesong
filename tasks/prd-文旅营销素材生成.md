## 问题

景区运营、宣传和内容人员需要持续制作营销素材，但文案、图片、艺术字和页面排版通常分散在多个工具与角色中。Demo 需要证明：内部人员只选择模板并输入一句话，系统就能通过可替换提示词和模型适配器返回一整套标题、正文、标签与图片页面。

## 目标

- G-1：提供无需学习提示词的清晰生成入口，并允许用参考图约束生成内容。
- G-2：用两套工作流（原创 IP 商品化、小红书图鉴创作）验证同一生成骨架可以承载不同文旅营销形式。
- G-3：把队友的正式提示词隔离在模板层，后续替换时不修改公共 API 和页面主流程。
- G-4：在无真实模型密钥时通过 Mock 模式完整演示；接入真实模型时仅替换 Provider 配置。
- G-5：图片生成局部失败时仍交付可用文案和成功页面。
- G-6：让用户在同一台电脑上重新打开、复制和下载最近生成的完整素材。
- G-7：将临时单页 Demo 升级为有明确一级、二级和三级页面的黔景智作产品：首页直接创作，模板列表与详情负责选择和理解，结果与历史负责交付和复用。
- G-8：以“场景化工作流”承载不同模板的输入、提示词、脚本规则和输出结构；公共模型 Provider 与基础设施复用，场景流程彼此隔离。
- G-9：支持小红书图鉴类模板：用户输入一句带数量的选题，自动生成清单、封面图、正文页图和发布文案素材包。
- G-10：支持原创 IP 场景通过 IP 素材库固定形象身份，后续生成请求自动注入已锁定的 IP 参考图和描述，减少重复上传。

## 非目标

- NG-1：不做登录、账号权限、收藏和后端业务数据库。
- NG-2：普通场景不保证固定 IP 跨次一致性和人物身份保持；只有显式使用原创 IP 工作流并绑定已锁定 IP Profile 时，才提供“参考图和固定描述自动注入”的一致性约束，不承诺模型绝对还原。
- NG-3：不做多轮对话、自主规划型 Agent、知识库和事实校验。
- NG-4：不做图片生成后的字体替换、Canvas/SVG 文字叠加或人工套版。
- NG-5：不做视频生成、社交平台自动发布和云端素材管理。
- NG-6：不做跨设备历史同步、后端参考素材自动过期、用户自助删除后端素材和存量素材管理后台。

## 成功标准

- SC-1：两个模板均可选择并提交合法输入：原创 IP 提交产品描述并上传一张产品图；图鉴提交含 2～36 数量的选题，可选上传最多 4 张合法参考图（只影响画面视觉，不改变清单事实）。
- SC-2：Mock 模式返回非空标题、正文、标签及模板要求的页面数组。
- SC-3：文案提示词和视觉规划提示词可独立替换，且默认并行执行。
- SC-4：视觉规划结果能拆成封面页、内容页、结尾页等动态页面，并并行调用图片 Provider。
- SC-5：任意单页失败时响应为 `partial`，成功页面和完整文案仍可展示、复制和下载。
- SC-6：用户可分别复制标题、正文和标签，下载单张图片及完整素材包。
- SC-7：无模型密钥时前后端可以启动，完成一次端到端生成流程。
- SC-8：前端构建、后端单元/集成测试和 API 冒烟测试通过。
- SC-9：上传参考图在生成完成后仍保存在后端，使用随机素材 ID 访问，目录不可浏览。
- SC-10：成功或部分成功结果自动保存在用户电脑 IndexedDB，刷新后可查看最近 20 条完整历史。
- SC-11：历史记录支持打开、复制、重新下载、单条删除和清空；本机删除不触发后端参考素材删除。
- SC-12：主页、全部模板、模板详情、生成结果、历史列表和历史详情通过稳定路由组织；原创 IP 首次档案配置保留必要创建路由，浏览器刷新和前进后退不会丢失可恢复结果。
- SC-13：桌面、平板和手机端均遵守统一的色彩、间距、圆角、阴影、排版、组件状态和响应式规范，并通过真实浏览器截图与关键流程验收。
- SC-14：小红书图鉴工作流对“贵阳的 12 种美食”等标题可完成数量提取、清单 JSON 校验、封面和正文页生成，并输出标题、正文、标签、清单 JSON 和图片序列。
- SC-15：原创 IP 工作流首次配置 IP 后，后续生成不要求用户重复上传 IP 参考图；生成请求能按 IP Profile 自动携带参考图和锁定描述。

## 核心用户与场景

### 场景 1：生成整套文旅素材

- 用户：景区运营、宣传或营销人员
- 触发：临时收到活动宣传或内容生产任务
- 操作：选择模板，输入一句话，点击“开始生成”
- 结果：得到标题、正文、标签和一组完整图片页面

### 场景 2：使用参考图生成

- 用户：景区内部营销人员
- 触发：需要参考既有 IP、人物或风景素材
- 操作：选择模板，上传最多 4 张参考图，输入一句话并生成
- 结果：模板和模型获得参考素材，后端持续保留原始上传文件

### 场景 3：查看本机历史

- 用户：同一台电脑、同一浏览器的景区内部人员
- 触发：需要继续使用之前生成的素材
- 操作：打开历史记录，选择某条记录
- 结果：无需重新请求模型即可查看、复制和下载完整素材

### 场景 4：替换正式提示词

- 用户：负责内容策略的队友或开发人员
- 触发：正式文案提示词和视觉提示词交付
- 操作：只修改对应模板的两套提示词
- 结果：前端、公共 API、Provider 接口和其他模板保持不变

### 场景 5：图片部分失败

- 用户：景区内部人员
- 触发：多页图片生成时部分调用失败
- 操作：查看返回结果
- 结果：文案及成功页面正常展示，失败页面明确标记，用户可重新生成整套素材

### 场景 6：从主页直接创作

- 用户：需要重复生产和复用素材的景区内部运营人员
- 触发：打开产品准备快速生产一套素材
- 操作：使用默认图鉴模板输入一句话，或横向切换模板后直接生成；历史从顶部右侧图标进入
- 结果：不经过独立表单页即可开始常用生成，生成结果仍进入独立详情页

### 场景 7：生成小红书图鉴素材

- 用户：文旅内容运营人员
- 触发：需要制作“贵阳的 12 种美食”“旅行必带的 10 件物品”等数量型图鉴内容
- 操作：选择图鉴模板，输入包含数量的选题标题并提交
- 结果：系统生成清单 JSON、1 张封面图、若干正文页图，以及 3 个候选标题、正文和标签；最终打包为可发布素材

### 场景 8：使用固定原创 IP 生成内容

- 用户：品牌或 IP 运营人员
- 触发：已经有一套标准 IP 形象，希望在不同产品内容中重复使用
- 首次配置：上传一张标准 IP 参考图，系统生成 IP 描述草稿，用户确认后锁定为 IP Profile
- 日常操作：用户输入产品描述或一句话需求，选择已锁定 IP（默认可自动选中）并生成
- 结果：后端自动携带 IP 参考图和固定描述；IP 身份保持约束，动作、姿态和应用位置由具体场景规划

## 场景化工作流

系统不使用自主规划型 Agent，而是采用“场景注册表 + 独立工作流 + 公共 Provider”的结构。每个场景可以拥有自己的输入规范、提示词集合、确定性脚本规则和输出数据结构；LLM 与生图模型通过公共适配器调用。

### 工作流注册

首批工作流包括：

| 工作流 | 输入 | 核心过程 | 输出 |
|---|---|---|---|
| `xhs-atlas` | 含数量的选题标题、最多 4 张参考图 | 标题规范化 → 清单 JSON → 校验 → 分页 → 封面/正文页生图 → 小红书文案 | 封面图 + 正文页图 + 文案 JSON + 清单 JSON |
| `original-ip` | 产品图、产品描述、锁定 IP Profile | 品牌视觉分析 → 画面规划 → 确定性拼接生图提示词 → 按职责生成图片 | 品牌/产品图片 + 营销文案 |

旧 `generic-marketing` 与旧四模板合同已删除；系统中只有以上两套工作流。

工作流与模板解耦：模板负责用户可见入口和视觉提示词资产，工作流负责执行顺序和业务规则。提示词全部保存在后端，禁止下发前端；不建立 `agent/` 目录，也不把场景规则集中到单个服务文件。

### `xhs-atlas` 小红书图鉴流程

1. 脚本从用户标题提取数量 `N` 和量词，并将 `N` 规范化到 2～36；无数量时报错，超过 36 时钳制到 36 并提示用户。
2. 调用清单提示词生成纯 JSON；脚本校验 `items.length === N`、字段非空、名称不重复，失败后最多重试一次。
3. 脚本按每页最多 6 条计算正文页，封面网格、页标签、起止序号和分页金句均由确定性代码生成。
4. 填充封面生图模板，生成 1 张封面；逐页填充正文生图模板，生成 K 张正文页。图片失败时保留失败页位置并返回部分成功。
5. 使用标题和清单 JSON 调用文案提示词，生成 3 个候选标题、正文和 10～12 个标签。
6. 打包封面、正文页、文案 JSON 和清单 JSON；封面必须排在图片序列第一位。

清单条目必须分为 `name`、`line1`、`line2`、`punch` 四层信息：封面使用身份层和钩子层，正文页使用实操层和点睛层，小红书正文只做点名安利，不重复罗列全部条目。

### `original-ip` IP 素材库

IP 素材库保存长期复用的 IP Profile，不与本次请求临时上传的参考素材混用。每个 Profile 至少包含：唯一 ID、标准参考图、固定文字描述和锁定状态。首次配置时允许多模态模型生成描述草稿，但必须由用户确认后才可锁定。

后续生成只传 `ipProfileId`，后端自动读取参考图并注入图片模型请求；IP 描述作为提示词中的身份约束，动作、神态、尺度和载体由场景提示词决定。系统只承诺“自动携带固定参考上下文”，不承诺模型绝对还原。

## 产品结构与页面职责

产品采用“全宽顶部导航 + 主页直接生成 + 模板浏览/详情 + 独立结果与历史”的多页面结构。正式首页细则以[黔景智作首页与导航体验设计](../docs/superpowers/specs/2026-08-29-黔景智作首页与导航体验-design.md)为最新依据，通用结果与历史规范继续沿用[产品体验与界面设计规范](../docs/文旅营销素材生成-产品体验与界面设计规范.md)。

| 层级 | 页面 | 建议路由 | 核心职责 |
|---|---|---|---|
| 一级 | 主页 | `/` | 默认选中小红书图鉴；输入一句话、可选加图并直接生成 |
| 一级 | 全部模板 | `/templates` | 浏览两套工作流模板、理解用途并带回主页使用 |
| 一级 | 历史记录 | `/history` | 查看、打开、删除和清空本机历史 |
| 二级 | 模板详情 | `/templates/:templateId` | 展示预览、场景、输入建议、示例与输出，并返回主页创作 |
| 二级（例外） | 原创 IP 档案配置 | `/templates/original-ip/create` | 仅在尚无锁定 IP Profile 时完成首次必要配置 |
| 三级 | 生成结果详情 | `/results/:requestId` | 查看整套图片和文案、复制、下载、重新生成 |
| 三级 | 历史结果详情 | `/history/:recordId` | 从本机历史恢复结果，并复用结果详情组件与操作能力 |

页面职责规则：

- 主页承担完整生成入口，不展示最近任务、统计卡片、结果或完整历史。
- 全部模板以真实示意图展示差异；“使用模板”回主页并选中模板，“查看详情”进入独立详情。
- 模板详情只负责解释，不重复生成表单；日常生成统一回到主页。
- 原创 IP 已有锁定档案时直接从主页生成；尚无档案时保留输入和产品图并进入必要配置页。
- 生成成功或部分成功后进入独立结果详情；结果详情使用缩略图导航、主图片预览和文案操作区组织内容。
- 历史详情与新生成结果复用同一套结果组件，禁止维护两套行为不同的结果页面。
- 单张图片允许进入沉浸预览，但不增加在线编辑、Canvas 排版或图片文字修改能力。
- 所有尺寸使用全宽顶部导航：左侧品牌、中部“主页 / 全部模板”、右侧历史图标；活动页签归属与路由一致。
- Trae 粒子显影 Canvas 只在主页挂载；其他页面静态显示，减少动态效果时不启动动画。

## 需求

### 功能需求

- FR-1：前端必须展示 `original-ip` 原创 IP 商品化与 `xhs-atlas` 小红书图鉴创作两个模板；旧四模板（`ip-image`、`travel-cards`、`scenery-collage`、`people-collage`）及其预览图、旧参考图数据已删除，旧创建路由返回“没有找到这个模板”。
- FR-2：用户必须选择模板并提交工作流要求的最小输入：原创 IP 输入产品描述并上传一张产品图（首次需初始化并锁定 IP 档案）；图鉴输入含数量的选题，可选上传参考图。
- FR-3：前端必须支持最多 4 张参考图的选择、预览、移除与上传；支持 JPG、PNG、WebP，单张不超过 10MB。
- FR-4：后端必须提供参考素材上传接口，对扩展名、MIME、文件签名、大小和数量执行校验。
- FR-5：后端必须以随机不可猜测的 `assetId` 和安全文件名持久保存参考图，禁止目录浏览；生成完成不自动删除。
- FR-6：点击“开始生成”后，前端按工作流提交：原创 IP 提交 `ipProfileId`、`productAssetId` 与 `productDescription`；图鉴提交规范化后的 `topic` 和最多 4 个 `referenceAssetIds`。
- FR-7：生成接口必须拒绝不存在或不合法的参考素材 ID。
- FR-8：后端必须从模板注册表读取用户可见文案提示词和视觉规划提示词，提示词不得下发前端。
- FR-9：文案和视觉规划分支必须能获取参考素材信息或模型可用输入；具体使用由模板和 Provider 决定。
- FR-10：文案分支必须输出 `title`、`body`、`tags`；视觉分支必须输出动态 `pages` 计划。
- FR-11：文案分支与视觉规划分支默认并行运行，并共享同一模板、用户输入和参考素材。
- FR-12：每个视觉页面计划必须包含页面 ID、页面角色、完整图片提示词和文件名；提示词负责描述画面文字、艺术字体和文字排版。
- FR-13：后端必须根据视觉页面计划调用图片 Provider；多个页面默认并行，单页失败不得取消其他页面。
- FR-14：图片模型必须生成包含文字和艺术排版的完整图片，系统不得执行后置字体渲染。
- FR-15：生成接口必须返回 `requestId`、`workflowId`、`status`、`copy`、`pages` 和 `warnings`；图鉴结果额外返回 `topic` 与 `list`，原创 IP 结果额外返回 `ipProfileId`、`ipProfileVersion` 与可选 `overview`。
- FR-16：当文案生成失败时返回失败响应；当部分图片失败时返回 `partial` 和成功结果。
- FR-17：前端必须展示生成中、成功、部分成功和失败状态，生成中禁止重复提交。
- FR-18：前端必须支持分别复制标题、正文、标签，并下载成功图片。
- FR-19：前端必须支持下载完整素材包，至少包含成功图片和 UTF-8 文案文件。
- FR-20：成功或部分成功结果必须自动写入用户浏览器 IndexedDB，保存模板、输入、参考图本地副本、生成文案、页面图片 Blob、状态和时间。
- FR-21：本机历史默认最多保留最近 20 条；写入第 21 条时删除最旧本机记录。
- FR-22：历史记录必须支持按时间倒序查看、打开详情、复制文案、重新下载、单条删除和清空。
- FR-23：删除或清空本机历史不得删除后端持久参考素材。
- FR-24：IndexedDB 配额不足时，前端必须优先删除最旧记录并重试；仍失败时保留本次结果并提示历史保存失败。
- FR-25：系统必须提供确定性 Mock 文案、Mock 视觉规划和 Mock 图片 Provider，未配置密钥时默认使用 Mock。
- FR-26：真实文案/视觉规划 Provider 和图片 Provider 必须通过后端环境变量选择与配置，密钥不得出现在客户端构建产物中。
- FR-27：模板必须以独立模块维护；修改某个模板的提示词不得影响其他模板。
- FR-28：后端不持久化生成历史或生成结果业务记录；只持久保存上传的参考素材。
- FR-29：后端参考素材暂不提供用户删除接口和自动清理任务，由管理员手动清理运行时目录。
- FR-30：前端必须提供主页、全部模板、模板详情、生成结果、历史列表和历史详情独立路由；原创 IP 首次配置保留兼容创建路由。
- FR-31：桌面、平板和手机均使用不遮挡内容的全宽顶部导航；左侧品牌返回主页，中部为主页/全部模板，右侧只放历史图标。
- FR-32：首页必须默认选中 `xhs-atlas`，`original-ip` 排在其后；输入、附件、生成与常用模板横向选择均在主页完成，不展示最近任务和统计卡片。
- FR-33：首页模板卡片以“名称在上、图片在下”呈现；点击卡片只切换选择，小号“详情”进入 `/templates/:templateId`，切换时保留输入和附件。
- FR-34：全部模板必须用真实视觉预览展示两套工作流，并同时提供“使用模板”返回主页和“查看详情”进入详情页两类操作。
- FR-35：模板详情必须展示预览、适用场景、输入建议、示例和输出；不重复完整生成表单。原创 IP 未锁定档案时才进入配置页。
- FR-36：创建页必须分别处理客户端校验、参考图上传、生成请求和本机保存等真实可知状态；后端未提供百分比或内部阶段时不得伪造进度。
- FR-37：成功或部分成功结果必须进入独立结果详情页；结果详情必须提供页面缩略图导航、当前图片大预览、完整文案、标签、状态、复制、单图下载和素材包下载。
- FR-38：历史结果详情必须复用生成结果详情组件；从本机历史打开时不得重新调用模型即可完成查看、复制和下载。
- FR-39：单张图片预览必须支持关闭、键盘操作、前后切换和单图下载；不得在本次 MVP 中扩展为在线图片编辑器。
- FR-40：部分成功结果必须保留失败页面在整套页面中的原始顺序，展示成功和失败数量，并允许下载成功图片与完整文案。
- FR-41：历史列表必须使用记录中保存的 `createdAt` 展示真实时间，不得在渲染时生成新的当前时间。
- FR-42：删除单条或清空本机历史前必须明确影响范围；删除不会触发后端参考素材删除，也不会影响已下载文件。
- FR-43：后端必须通过场景注册表选择工作流；每个工作流独立维护输入规范、提示词、确定性脚本规则和输出映射，公共 Provider 与基础设施可复用。
- FR-44：系统必须支持 `xhs-atlas` 图鉴工作流：标题数量规范化、清单 JSON 生成与校验、确定性分页、封面/正文页生图、小红书文案生成和素材包打包。
- FR-45：`xhs-atlas` 必须支持 2～36 条目；无数量时返回明确业务错误，超过 36 时钳制到 36 并产生 warning；清单 JSON 校验失败最多自动重试一次。
- FR-46：`xhs-atlas` 的封面固定为 1 张，正文页按每页最多 6 条动态生成；图片序列和素材包中封面排在正文页之前。
- FR-47：`xhs-atlas` 输出必须包含 3 个候选标题、正文、标签、清单 JSON，以及成功或失败状态和对应图片页面。
- FR-48：系统必须支持 IP Profile 素材库；Profile 至少包含 `ipProfileId`、标准参考图、固定描述和 `locked` 状态。
- FR-49：原创 IP 首次配置必须支持上传标准参考图、生成描述草稿、用户确认和锁定；未锁定 Profile 不得作为默认固定 IP 注入。
- FR-50：绑定已锁定 IP Profile 的生成请求只需传 `ipProfileId`，后端自动读取参考图和固定描述并注入对应工作流；前端不得接收完整内部提示词。
- FR-51：IP Profile 参考图和本次用户产品参考图必须分开管理；删除本机历史不得删除 IP 素材库文件或后端临时参考素材。

### 非功能需求

- NFR-1：前后端均使用 TypeScript，公共请求和响应类型保持单一来源。
- NFR-2：用户输入必须在前后端双重校验，错误响应不得回显密钥、完整内部提示词或 Provider 原始敏感信息。
- NFR-3：Provider 调用必须有可配置超时；超时和网络错误转换为统一业务错误或页面失败状态。
- NFR-4：Mock 端到端流程在本机启动后应可重复执行，不依赖外部网络。
- NFR-5：前端在手机和桌面常见浏览器宽度下可完成模板选择、输入、预览、复制和下载。
- NFR-6：核心模块保持单一职责，模板、编排、Provider、下载和 UI 状态不得集中到一个超大文件。
- NFR-7：生成请求、Provider 失败和页面失败应输出不含提示词正文与密钥的结构化服务日志。
- NFR-8：参考素材目录必须位于 Git 忽略的运行时数据路径，拒绝路径穿越、可执行文件和伪造图片内容。
- NFR-9：参考素材 URL 使用高熵随机 ID，不暴露原始文件系统路径；由于 Demo 无鉴权，必须在已知限制中标明“持有 URL 即可访问”。
- NFR-10：IndexedDB 读写失败不得导致生成接口失败，历史模块与当前生成状态必须隔离。
- NFR-11：前端必须使用统一设计 Token 管理色彩、间距、圆角、阴影和排版，不得在页面组件中持续新增无语义的一次性数值。
- NFR-12：产品界面采用单一山湖青主色和冷灰中性色；语义状态色只表达成功、警告、错误和信息，不承担装饰作用。
- NFR-13：所有交互组件必须覆盖默认、悬停、键盘聚焦、按下、禁用、加载和错误等适用状态，正文和交互文字满足 WCAG AA 对比度。
- NFR-14：普通页面层级优先使用表面色差和细边界，明显阴影仅用于菜单、浮层、沉浸预览和弹窗。
- NFR-15：360px、390px、768px、1024px、1440px 和 1600px 代表宽度下不得出现阻断操作的溢出、遮挡、按钮换行或不可访问内容。
- NFR-16：动效只表达状态、反馈、加载或层级切换，常规时长控制在 120-280ms，并遵守 `prefers-reduced-motion`。

## 假设

- A-1：普通工作流可使用文字和可选参考图，但不要求固定 IP 或人物跨次一致性；原创 IP 工作流通过锁定 Profile 提供额外参考上下文。
- A-2：队友后续提供的提示词能够输出符合约定结构的文案和视觉页面计划。
- A-3：同一文案模型 Provider 可以承载文案生成和视觉规划，也允许未来配置为不同模型。
- A-4：图片 Provider 支持通过文字提示词生成带中文、艺术字体和排版的完整图片；实际文字正确率属于模型效果风险。
- A-5：具体真实模型和部署环境在骨架完成后确定。
- A-6：用户使用支持 IndexedDB 的现代浏览器，并接受历史仅存在于当前电脑当前浏览器。
- A-7：后端运行环境提供可持久写入的本地目录；重启服务不会清空该目录。

## 依赖与约束

- React、TypeScript、Vite 前端。
- Node.js、TypeScript 后端 HTTP API。
- 共享类型模块供前后端复用。
- 后端使用文件系统持久保存参考图，不引入业务数据库。
- 浏览器使用 IndexedDB 保存最近 20 条完整历史。
- Mock Provider 必须随项目提供；真实 Provider 通过适配器接入。
- 正式提示词属于场景配置，不写入前端，不散落在编排服务中；长提示词允许以 Markdown 文件维护，由后端加载并按约定槽位确定性填充。
- 场景脚本中的数量提取、分页、网格和 JSON 校验属于确定性代码，不交给 LLM 自主决定。
- IP Profile 参考图和描述属于后台配置资产；普通请求的临时参考图不自动升级为固定 IP。
- 前端页面结构与视觉实现必须遵守 `docs/文旅营销素材生成-产品体验与界面设计规范.md`；PRD 负责产品职责和验收，设计规范负责具体视觉与交互规则。

## 风险与边界情况

- 图片模型可能生成错误中文、错别字或不符合预期的艺术字；Demo 通过重新生成和独立可复制文案兜底，不做后置文字修复。
- 即使上传参考图，具体图片 Provider 也可能无法保证固定 IP 和人物跨页面、跨请求高度一致；普通工作流只验证素材传递和模板能力，原创 IP 工作流额外验证 Profile 注入链路。
- 两套提示词并行可能造成用户文案和图片页面文字不完全一致；提示词应共享主题、受众和关键卖点约束，未来可按模板切换为先文案后视觉。
- 多页并行调用可能触发 Provider 并发或限额；Provider 适配器需要预留并发控制配置。
- 浏览器对批量下载行为限制不同；完整素材包采用单文件下载，单图下载逐张触发。
- 参考素材在后端无自动清理，可能持续占用磁盘；Demo 由管理员手动清理，生产版必须增加配额、保留期和权限。
- Demo 无登录鉴权，持有高熵素材 URL 的人可能访问参考图；不得用于生产敏感素材。
- IndexedDB 容量受浏览器和磁盘限制；写入失败不能影响当前结果使用。
- 多页面改造后，当前结果、路由参数和 IndexedDB 恢复必须使用同一结果结构；若只依赖组件内存，刷新三级结果页会丢失内容。
- 重新生成历史任务时，原参考素材可能已经不可用；前端必须保留模板和文字需求，并明确要求重新上传失效参考图。
- 小红书图鉴清单可能出现数量不符、重复名称或字段缺失；必须由脚本校验并最多重试一次，不能直接把未校验 JSON 交给后续生图步骤。
- 图鉴封面和正文页提示词包含大量中文文字，图片模型可能出现乱码或错字；系统保留可复制的文案 JSON 和清单 JSON 作为文字兜底，不增加后置排版层。
- IP Profile 一旦锁定后若允许静默修改，会破坏跨请求一致性；修改必须创建新版本或显式解锁，当前 MVP 只允许锁定后只读使用。
