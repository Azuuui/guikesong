## 问题

景区运营、宣传和内容人员需要持续制作营销素材，但文案、图片、艺术字和页面排版通常分散在多个工具与角色中。Demo 需要证明：内部人员只选择模板并输入一句话，系统就能通过可替换提示词和模型适配器返回一整套标题、正文、标签与图片页面。

## 目标

- G-1：提供一个无需学习提示词的单页生成入口，并允许用参考图约束生成内容。
- G-2：用四个模板验证同一生成骨架可以承载不同文旅营销形式。
- G-3：把队友的正式提示词隔离在模板层，后续替换时不修改公共 API 和页面主流程。
- G-4：在无真实模型密钥时通过 Mock 模式完整演示；接入真实模型时仅替换 Provider 配置。
- G-5：图片生成局部失败时仍交付可用文案和成功页面。
- G-6：让用户在同一台电脑上重新打开、复制和下载最近生成的完整素材。

## 非目标

- NG-1：不做登录、账号权限、收藏和后端业务数据库。
- NG-2：不保证固定 IP 跨次一致性和人物身份保持。
- NG-3：不做多轮对话、自主规划型 Agent、知识库和事实校验。
- NG-4：不做图片生成后的字体替换、Canvas/SVG 文字叠加或人工套版。
- NG-5：不做视频生成、社交平台自动发布和云端素材管理。
- NG-6：不做跨设备历史同步、后端参考素材自动过期、用户自助删除后端素材和存量素材管理后台。

## 成功标准

- SC-1：四个模板均可选择并提交 2—500 字的一句话需求，以及可选的最多 4 张合法参考图。
- SC-2：Mock 模式返回非空标题、正文、标签及模板要求的页面数组。
- SC-3：文案提示词和视觉规划提示词可独立替换，且默认并行执行。
- SC-4：视觉规划结果能拆成封面页、内容页、结尾页等动态页面，并并行调用图片 Provider。
- SC-5：任意单页失败时响应为 `partial`，成功页面和完整文案仍可展示、复制和下载。
- SC-6：用户可分别复制标题、正文和标签，下载单张图片及完整素材包。
- SC-7：无模型密钥时前后端可以启动，完成一次端到端生成流程。
- SC-8：前端构建、后端单元/集成测试和 API 冒烟测试通过。
- SC-9：上传参考图在生成完成后仍保存在后端，使用随机素材 ID 访问，目录不可浏览。
- SC-10：成功或部分成功结果自动保存在用户电脑 IndexedDB，刷新后可查看最近 20 条完整历史。
- SC-11：历史记录支持打开、复制、重新下载、单条删除和清空；本机删除不触发后端参考素材删除。

## 核心用户与场景

### 场景 1：生成整套文旅素材

- 用户：景区运营、宣传或营销人员
- 触发：临时收到活动宣传或内容生产任务
- 操作：选择模板，输入一句话，点击“一键生成”
- 结果：得到标题、正文、标签和一组完整图片页面

### 场景 2：使用参考图生成

- 用户：景区内部营销人员
- 触发：需要参考既有 IP、人物或风景素材
- 操作：选择模板，上传最多 4 张参考图，输入一句话并生成
- 结果：模板和模型获得参考素材，后端持续保留原始上传文件

### 场景 3：查看本机历史

- 用户：同一台电脑、同一浏览器的景区内部人员
- 触发：需要继续使用之前生成的素材
- 操作：打开历史记录，选择某条记录
- 结果：无需重新请求模型即可查看、复制和下载完整素材

### 场景 4：替换正式提示词

- 用户：负责内容策略的队友或开发人员
- 触发：正式文案提示词和视觉提示词交付
- 操作：只修改对应模板的两套提示词
- 结果：前端、公共 API、Provider 接口和其他模板保持不变

### 场景 5：图片部分失败

- 用户：景区内部人员
- 触发：多页图片生成时部分调用失败
- 操作：查看返回结果
- 结果：文案及成功页面正常展示，失败页面明确标记，用户可重新生成整套素材

## 需求

### 功能需求

- FR-1：前端必须展示 `ip-image`、`travel-cards`、`scenery-collage`、`people-collage` 四个模板。
- FR-2：用户必须选择模板并输入一句 2—500 字需求；所有模板均可选上传参考图。
- FR-3：前端必须支持最多 4 张参考图的选择、预览、移除与上传；支持 JPG、PNG、WebP，单张不超过 10MB。
- FR-4：后端必须提供参考素材上传接口，对扩展名、MIME、文件签名、大小和数量执行校验。
- FR-5：后端必须以随机不可猜测的 `assetId` 和安全文件名持久保存参考图，禁止目录浏览；生成完成不自动删除。
- FR-6：点击“一键生成”后，前端向后端提交 `templateId`、规范化后的 `userPrompt` 和最多 4 个 `referenceAssetIds`。
- FR-7：生成接口必须拒绝不存在或不合法的参考素材 ID。
- FR-8：后端必须从模板注册表读取用户可见文案提示词和视觉规划提示词，提示词不得下发前端。
- FR-9：文案和视觉规划分支必须能获取参考素材信息或模型可用输入；具体使用由模板和 Provider 决定。
- FR-10：文案分支必须输出 `title`、`body`、`tags`；视觉分支必须输出动态 `pages` 计划。
- FR-11：文案分支与视觉规划分支默认并行运行，并共享同一模板、用户输入和参考素材。
- FR-12：每个视觉页面计划必须包含页面 ID、页面角色、完整图片提示词和文件名；提示词负责描述画面文字、艺术字体和文字排版。
- FR-13：后端必须根据视觉页面计划调用图片 Provider；多个页面默认并行，单页失败不得取消其他页面。
- FR-14：图片模型必须生成包含文字和艺术排版的完整图片，系统不得执行后置字体渲染。
- FR-15：生成接口必须返回 `requestId`、`templateId`、`status`、`copy`、`pages` 和 `warnings`。
- FR-16：当文案生成失败时返回失败响应；当部分图片失败时返回 `partial` 和成功结果。
- FR-17：前端必须展示生成中、成功、部分成功和失败状态，生成中禁止重复提交。
- FR-18：前端必须支持分别复制标题、正文、标签，并下载成功图片。
- FR-19：前端必须支持下载完整素材包，至少包含成功图片和 UTF-8 文案文件。
- FR-20：成功或部分成功结果必须自动写入用户浏览器 IndexedDB，保存模板、输入、参考图本地副本、生成文案、页面图片 Blob、状态和时间。
- FR-21：本机历史默认最多保留最近 20 条；写入第 21 条时删除最旧本机记录。
- FR-22：历史记录必须支持按时间倒序查看、打开详情、复制文案、重新下载、单条删除和清空。
- FR-23：删除或清空本机历史不得删除后端持久参考素材。
- FR-24：IndexedDB 配额不足时，前端必须优先删除最旧记录并重试；仍失败时保留本次结果并提示历史保存失败。
- FR-25：系统必须提供确定性 Mock 文案、Mock 视觉规划和 Mock 图片 Provider，未配置密钥时默认使用 Mock。
- FR-26：真实文案/视觉规划 Provider 和图片 Provider 必须通过后端环境变量选择与配置，密钥不得出现在客户端构建产物中。
- FR-27：模板必须以独立模块维护；修改某个模板的提示词不得影响其他模板。
- FR-28：后端不持久化生成历史或生成结果业务记录；只持久保存上传的参考素材。
- FR-29：后端参考素材暂不提供用户删除接口和自动清理任务，由管理员手动清理运行时目录。

### 非功能需求

- NFR-1：前后端均使用 TypeScript，公共请求和响应类型保持单一来源。
- NFR-2：用户输入必须在前后端双重校验，错误响应不得回显密钥、完整内部提示词或 Provider 原始敏感信息。
- NFR-3：Provider 调用必须有可配置超时；超时和网络错误转换为统一业务错误或页面失败状态。
- NFR-4：Mock 端到端流程在本机启动后应可重复执行，不依赖外部网络。
- NFR-5：前端在手机和桌面常见浏览器宽度下可完成模板选择、输入、预览、复制和下载。
- NFR-6：核心模块保持单一职责，模板、编排、Provider、下载和 UI 状态不得集中到一个超大文件。
- NFR-7：生成请求、Provider 失败和页面失败应输出不含提示词正文与密钥的结构化服务日志。
- NFR-8：参考素材目录必须位于 Git 忽略的运行时数据路径，拒绝路径穿越、可执行文件和伪造图片内容。
- NFR-9：参考素材 URL 使用高熵随机 ID，不暴露原始文件系统路径；由于 Demo 无鉴权，必须在已知限制中标明“持有 URL 即可访问”。
- NFR-10：IndexedDB 读写失败不得导致生成接口失败，历史模块与当前生成状态必须隔离。

## 接口合同

```ts
type GenerateRequest = {
  templateId: "ip-image" | "travel-cards" | "scenery-collage" | "people-collage";
  userPrompt: string;
  referenceAssetIds: string[];
};

type ReferenceAsset = {
  assetId: string;
  url: string;
  originalName: string;
  mediaType: "image/jpeg" | "image/png" | "image/webp";
  size: number;
  createdAt: string;
};

type GeneratedCopy = {
  title: string;
  body: string;
  tags: string[];
};

type GeneratedPage = {
  id: string;
  pageType: "cover" | "content" | "ending";
  filename: string;
  status: "succeeded" | "failed";
  imageUrl?: string;
  alt?: string;
  error?: string;
};

type GenerateResponse = {
  requestId: string;
  templateId: GenerateRequest["templateId"];
  status: "succeeded" | "partial";
  copy: GeneratedCopy;
  pages: GeneratedPage[];
  warnings: string[];
};
```

内部视觉规划合同：

```ts
type VisualPagePlan = {
  id: string;
  pageType: "cover" | "content" | "ending";
  imagePrompt: string;
  filename: string;
};

type VisualPlan = {
  pages: VisualPagePlan[];
};
```

## 假设

- A-1：Demo 可使用文字和可选参考图，但不要求固定 IP 或人物跨次一致性。
- A-2：队友后续提供的提示词能够输出符合约定结构的文案和视觉页面计划。
- A-3：同一文案模型 Provider 可以承载文案生成和视觉规划，也允许未来配置为不同模型。
- A-4：图片 Provider 支持通过文字提示词生成带中文、艺术字体和排版的完整图片；实际文字正确率属于模型效果风险。
- A-5：具体真实模型和部署环境在骨架完成后确定。
- A-6：用户使用支持 IndexedDB 的现代浏览器，并接受历史仅存在于当前电脑当前浏览器。
- A-7：后端运行环境提供可持久写入的本地目录；重启服务不会清空该目录。

## 依赖与约束

- React、TypeScript、Vite 前端。
- Node.js、TypeScript 后端 HTTP API。
- 共享类型模块供前后端复用。
- 后端使用文件系统持久保存参考图，不引入业务数据库。
- 浏览器使用 IndexedDB 保存最近 20 条完整历史。
- Mock Provider 必须随项目提供；真实 Provider 通过适配器接入。
- 正式提示词属于模板配置，不写入前端，不散落在编排服务中。

## 风险与边界情况

- 图片模型可能生成错误中文、错别字或不符合预期的艺术字；Demo 通过重新生成和独立可复制文案兜底，不做后置文字修复。
- 即使上传参考图，具体图片 Provider 也可能无法保证固定 IP 和人物跨页面、跨请求高度一致；MVP 只验证素材传递和模板能力。
- 两套提示词并行可能造成用户文案和图片页面文字不完全一致；提示词应共享主题、受众和关键卖点约束，未来可按模板切换为先文案后视觉。
- 多页并行调用可能触发 Provider 并发或限额；Provider 适配器需要预留并发控制配置。
- 浏览器对批量下载行为限制不同；完整素材包采用单文件下载，单图下载逐张触发。
- 参考素材在后端无自动清理，可能持续占用磁盘；Demo 由管理员手动清理，生产版必须增加配额、保留期和权限。
- Demo 无登录鉴权，持有高熵素材 URL 的人可能访问参考图；不得用于生产敏感素材。
- IndexedDB 容量受浏览器和磁盘限制；写入失败不能影响当前结果使用。
